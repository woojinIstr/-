기본 실행 모드는 Supabase 인증 및 FastAPI 서버 연결 모드입니다.
실행 방법과 현재 지원 범위는 [SERVER_SETUP.md](SERVER_SETUP.md)를 먼저 확인하세요.
원본 데모는 `VITE_APP_MODE=demo` 설정으로 별도 실행할 수 있습니다.

## 기존 데모 설명

Figma에서 설계한 「다음한끼」를 기반으로 만든 **React + Vite** 웹사이트입니다. 초기 MVP의 프론트엔드 시연용이며, **현재 백엔드·실제 AI·계정 인증은 연결되지 않았습니다.**

## 윈도우 노트북에서 실행

1. ZIP을 압축 해제합니다.
2. VS Code에서 `daeum-hankki-react` 폴더를 엽니다. (`파일 > 폴더 열기`)
3. VS Code 메뉴 `터미널 > 새 터미널`을 엽니다.
4. 다음 명령어를 **한 줄씩** 실행합니다.

```powershell
npm install
npm run dev
```

5. 터미널에 표시되는 `http://localhost:5173/` 주소를 브라우저에서 엽니다.

> PowerShell에서 스크립트 실행이 차단되면 VS Code 터미널 오른쪽 메뉴에서 **Command Prompt(명령 프롬프트)** 를 선택해 같은 명령을 실행하세요. 보안 정책을 바꿀 필요는 없습니다.

## 구현한 화면

- 홈: 재고·계획·장보기 요약
- 식재료: 직접 등록, 검색, 수정, 삭제, 수량·단위·보관 위치 관리
- 식사 계획: 날짜별 식사, 외식·취소·메뉴 변경, 실제 조리 완료
- AI 추천(데모): 시간·제외 재료·우선 재료에 따른 **규칙 기반** 예시 레시피 추천
- 변경 전후 비교 및 승인: 승인 전 식사 계획·자동 장보기 부족량 비교
- 장보기 목록 및 변경 이력: 자동 부족량, 수동 추가·구매 체크, 일부 계획 변경 되돌리기

## 핵심 데이터 규칙

- 계획 변경을 요청해도 승인 전까지 확정 계획은 바뀌지 않습니다.
- 외식·식사 취소만으로 **재고를 차감하지 않습니다**.
- 실제 조리 완료 시 입력한 사용량만 재고에서 차감합니다. 재고 부족 시 차감하지 않습니다.
- 자동 장보기 부족량 = `max(0, 확정된 모든 계획 식사의 해당 재료 총필요량 − 현재 재고량)`.
- 자동 계산된 장보기와 사용자가 직접 추가한 항목을 분리합니다.
- 같은 재료라도 단위가 다르면 자동 변환하지 않습니다(예: kg와 g). MVP에서 입력 단위를 일치시켜 주세요.

## 데이터 저장

브라우저의 `localStorage`에 저장됩니다. 다른 PC·브라우저와 동기화되지 않으며, 개발자 도구/브라우저 데이터 삭제 시 사라질 수 있습니다. 화면 왼쪽 하단에서 데모 데이터를 초기화할 수 있습니다.

## 팀원 B/C와 통합할 때

- B: FastAPI + Supabase의 API 명세(URL, 요청/응답 JSON, 인증, 오류)를 받아 `src/api.js` 등의 API 계층을 구현합니다. 현재는 로컬 상태만 사용합니다.
- C: 추천 API가 준비되면 `recommend()`의 규칙 기반 데모 로직을 교체합니다. 재고·장보기 산술 계산은 백엔드에서 재현 가능한 규칙으로 처리하는 것이 좋습니다.
- D: 변경 요청 → 전후 비교 → 승인 → 조리 완료 → 재고 차감의 통합 테스트를 수행합니다.

## 유의사항

이 프로젝트는 개발/시연용 MVP입니다. 실제 서비스 배포 전 사용자 인증, 서버 저장, 입력 검증, 동시성 제어, 중복 요청 방지, 배치/단위 정합성, 접근성 및 오류 처리가 추가로 필요합니다. 현재 추천 레시피의 조리 시간은 예시값이며 영양·의학적 판단을 제공하지 않습니다.
